# Архитектура

Как устроена IDE и почему именно так.

---

## Идея

Ядро не знает ни одной фичи. Нет «встроенного» редактора, терминала или проводника — всё это плагины. Ядро даёт только:

- реестр команд;
- шину событий;
- раскладку (регионы и слоты);
- мост к ОС на Rust.

Из этого следует, что **любая возможность — сменная**. Не нравится редактор — выкинь и поставь другой. Он не «расширение», а полноправный житель.

## Слои

```
┌─────────────────────────────────────────────┐
│  плагины (ESM, без сборки)                  │
│  explorer · editor · terminal · …           │
└───────────────────┬─────────────────────────┘
                    │ PluginContext
┌───────────────────▼─────────────────────────┐
│  ядро (TypeScript)                          │
│  commands · events · ui · storage · io      │
│  capabilities · services                    │
└───────────────────┬─────────────────────────┘
                    │ Tauri IPC
┌───────────────────▼─────────────────────────┐
│  бэкенд (Rust)                              │
│  fs · fs.tools · pty · proc · serial        │
│  storage · plugins · stream · logging       │
└─────────────────────────────────────────────┘
```

Плагин никогда не трогает файловую систему напрямую — только через сервисы. Это даёт единые ошибки, атомарность и защиту от побега из каталога.

## Ядро (TypeScript)

```
src/core/
  disposable.ts        Disposable / DisposableStore / DisposableBase
  errors.ts            PluginError, isolate()
  event-bus.ts         pub/sub, изолированный от падений подписчиков
  command-registry.ts  register/execute, каждый register → Disposable
  storage.ts           Storage + StorageNamespace (per-plugin)
  services/
    fs.ts              core.fs
    fs-tools.ts        fs.tools: поиск, наблюдение
    pty.ts             pty
    proc.ts            proc
    serial.ts          serial
    registry.ts        ServiceRegistry
  ui/
    layout.ts          регионы, размеры, сохранение в Storage
    slot.ts            DomUiHost: монтирование слотов
    positioning.ts     ZIndexPool: тиры
    titlebar.ts        кастомный заголовок окна
    splash.ts          экран загрузки
  plugin/
    api.ts             PluginContext — контракт для плагинов
    source.ts          PluginSource (InMemory, Filesystem)
    module-loader.ts   BlobModuleLoader (ESM через blob URL)
    ui-host.ts         UiHost — точка монтажа слотов
    context.ts         PluginContextImpl
    registry.ts        активные плагины и их dispose
    host.ts            PluginHost: activate/deactivate/reload
    capability-registry.ts
    io-registry.ts
  main.ts              bootstrap: core → host → activateAll
```

### Правила

- все `register*` возвращают `Disposable`;
- падение плагина не роняет ядро (`isolate*`);
- API только async и версионируется через манифест;
- запрещено: `document`/`window`/`fs` из плагина, синхронный API, хардкод раскладки.

### Жизненный цикл

```
scan → validate manifest → topological sort → activate
                                              ↓
                                    register commands/slots/IO
                                              ↓
                                     ctx.subscriptions
                                              ↓
deactivate → module.deactivate() → dispose subscriptions
```

При провале `activate` — полный откат: стили, IO-выходы, capability, подписки, запись в реестре.

### Горячая перезагрузка

Бэкенд следит за корнями плагинов и шлёт `plugins:changed` со списком `id` (после ~300 мс тишины). Хост перезагружает только изменившиеся, сохраняя порядок зависимостей. Правка `index.js` не требует перезапуска IDE.

## Бэкенд (Rust)

```
src-tauri/src/
  lib.rs         регистрация команд, состояние, гашение процессов
  error.rs       AppError: код + сообщение с путём
  paths.rs       проверка путей (побег, ADS, symlink)
  fs/
    mod.rs       файлы: атомарная запись, текст/бинарь, copy/move
    search.rs    поиск по проекту
    watch.rs     наблюдение с пакетированием
  pty.rs         терминал (ConPTY/PTY)
  proc.rs        процессы без PTY
  serial.rs      последовательные порты
  storage.rs     настройки
  plugins.rs     плагины + горячая перезагрузка
  stream.rs      шина событий: склейка, порядок, UTF-8
  logging.rs     лог в файл с ротацией
  utf8.rs        потоковый декодер UTF-8
```

### Принципы

**Плагин не должен вешать IDE.** Вывод схлопывается в пакеты (8 мс), запись в PTY идёт через ограниченную очередь в отдельном потоке, а определение выхода **опрашивает** процесс. Причина: ConPTY на Windows не отдаёт EOF после завершения дочернего процесса — если ждать EOF, `pty:exit` не приходит никогда. Это не теория: на этом ломался терминал, и поведение подтверждено тестом `probe_conpty_eof_behaviour`.

**Ошибка объясняет себя.** `AppError` сериализуется в строку `КОД: сообщение`, где сообщение содержит путь. Строка, а не объект, потому что плагины ловят `String(e)`; код при этом машиночитаем.

**Путь из плагина — недоверенный.** `Path::join` с абсолютным путём *заменяет* базу, поэтому склейка идёт только через `paths`: проверка компонентов, запрет `..`, ADS и абсолютных путей, затем канонизация и проверка вложенности (закрывает symlink-побеги).

**Данные не теряются.** Запись файлов и настроек: temp-файл рядом с целью → `fsync` → `rename`. Читатель видит либо старую версию целиком, либо новую. Повреждённый JSON откладывается в `.corrupt-*.json`, а IDE стартует.

**Процессы не остаются сиротами.** `cmd.exe → node → esbuild` — три процесса. При выходе гасятся деревья (`taskkill /T /F`), закрываются порты и наблюдатели.

**Память ограничена.** Завершённые сессии PTY и процессов сохраняют историю вывода для `replay()`, но вытесняются по счётчику — реестр не растёт бесконечно.

## Шина событий

Один поток-агрегатор на все потоки данных (PTY, процессы, порты). Зачем:

1. **Скорость.** `cargo build` даёт тысячи мелких чанков; отправлять каждый отдельным IPC-событием — тысячи сериализаций.
2. **Порядок.** Событие выхода обязано прийти *после* последних данных, иначе терминал «зависает» с недописанной строкой.
3. **Кодировка.** Декодер помнит хвост многобайтового символа между чанками.

Приёмник задаётся трейтом `Sink` — поэтому поведение проверяется тестами без окна.

## Раскладка

Регионы: `topbar`, `sidebar`, `main`, `bottom`, `statusbar`, `overlay`.

Плагин просит слот в регионе, получает `SlotHandle` с `element`. Ядро не хардкодит ни одной фичи — только раскладывает регионы и хранит их размеры в `Storage`.

Тиры z-index: `background` < `normal` < `raised` < `overlay` < `modal` < `system`.

## Сборка

| | |
|---|---|
| Frontend | TypeScript + Vite, нативный ES2022 |
| Backend | Rust, Tauri 2 |
| Плагины | чистый ESM, без сборки |
| Webview | системный (WebView2 на Windows) |

Зависимости в dev-профиле собираются с `opt-level = 2`: IDE ощутимо быстрее, инкремент нашего крейта остаётся быстрым.
